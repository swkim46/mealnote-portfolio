# 실행·검증·배포 안내

[식단노트](../README.md) / 구현 참고

이 문서는 코드를 직접 실행하거나 구조를 확인하려는 분을 위한 안내입니다. 설계 판단은 [README](../README.md)와 `docs/01`～`06`에, 운동·식단·인바디를 함께 보는 후속 구상은 [앞으로의 계획](07_앞으로의_계획.md)에 있습니다. 코드는 2026년 10월 27일 운영 버전(v1.7.2)을 공개용으로 정리한 사본입니다. 운영 주소와 운영 프로젝트 식별자는 지웠고, 문서 속 `https://mealnote.example`은 자리표시자입니다.

| 구성 | 사용한 것 |
|---|---|
| 화면 | React 19, Vite, vite-plugin-pwa(홈 화면에 추가해 쓰는 모바일 웹앱) |
| 서버 | Supabase: Postgres(행 단위 권한 규칙과 서버 함수), 로그인, 사진 저장소, 서버 기능 `send-push`, 예약 작업 `pg_cron` |
| 호스팅 | Cloudflare Pages(정적 파일 배포) |
| 인바디 결과지 인식 | Tesseract.js. 휴대폰 안에서 숫자만 읽고 사진은 저장하지 않습니다 |

## 환경

개발 DB는 맥 안의 로컬 Supabase이고, 운영 DB와 완전히 분리돼 있습니다. 로컬 Supabase는 Colima 위의 Docker로 띄우며, 앱에 필요한 DB·로그인·데이터 API·사진 저장소·API 관문만 켭니다.

| 환경 | DB | 화면 | 쓰는 곳 |
|---|---|---|---|
| 개발 | 로컬 Supabase | `npm run dev` | 개발과 검증 |
| 운영 | Supabase 서울 리전 | Cloudflare Pages | 실제 트레이너와 회원 |

환경 변수 파일은 모두 커밋하지 않습니다. 파일별로 들어갈 이름은 [`.env.example`](../.env.example)에 있습니다. 트레이너·운영자 등록 코드는 원문을 DB에 두지 않고 SHA-256 해시만 저장합니다. 이 저장소의 마이그레이션에는 예시 코드(`MEALNOTE-TRAINER`, `MEALNOTE-ADMIN`)의 해시가 들어 있습니다.

## 처음 실행

필요한 것: Node.js 22 이상, Supabase CLI, Colima와 Docker, Playwright 브라우저(`npx playwright install chromium`).

```sh
npm ci
npm run db:start     # Colima와 로컬 Supabase 켜기(처음 약 4분, 이후 약 45초)
npm run push:setup   # 처음 한 번(그리고 db:reset 뒤): 로컬 알림 키·호출 비밀·송신 스위치 준비
npm run dev          # http://localhost:5173 · 같은 와이파이의 휴대폰은 http://<맥 IP>:5173
npm run db:stop      # 다 끝나면 끄기(데이터는 남음)
```

휴대폰도 개발 서버를 거쳐 로컬 DB에 붙습니다(`vite.config.ts`의 프록시). 기본 응원 문구 원본은 `supabase/functions/_shared/quotes.ts`이고, 앱과 아침 응원 알림이 같은 목록을 씁니다.

## 검증

```sh
npm run check        # 전체. 끝나면 시험 계정·의견을 자동으로 지웁니다
npm run check:unit   # 부분 실행: unit · component · backend · race · push · update · ocr · e2e
npm run lint
npm run phone:test   # 실제 휴대폰으로 알림 시험: 로컬 DB를 쓰는 빌드에 임시 https 주소(Cloudflare 터널)를 붙입니다
```

| 검증 | 스크립트 | 확인하는 것 |
|---|---|---|
| 규칙 | `scripts/unit-check.mjs` | 측정 사이 변화 문장, 인바디 숫자 고르기, 새 버전 자동 적용 시점 |
| 화면 조각 | `scripts/component-check.mjs` | 늦은 응답·실패·재시도처럼 실제 서버로 만들기 어려운 경계 상황(서버 응답만 흉내 냄) |
| 권한 | `scripts/backend-check.mjs` | 역할별로 읽고 쓸 수 있는 범위, 거부 사유, 가입·복구·되찾기 |
| 경쟁 상황 | `scripts/race-check.mjs` | 같은 계정에 요청이 동시에 들어올 때 하나만 성공하는지(행 잠금으로 실제 동시 요청을 만듦) |
| 알림 | `scripts/push-check.mjs` | 알림 생성 규칙, 보내기 직전 재확인, 재시도, 송신 스위치 |
| 새 버전 적용 | `scripts/update-check.mjs` | 실제 빌드 두 개를 번갈아 띄워 입력 중인 글이 지워지지 않는지 |
| 인바디 인식 | `scripts/ocr-check.mjs` | 지어낸 값으로 만든 결과지 이미지에서 네 값 인식 |
| 휴대폰 시험 보호 | `scripts/phonetest-guard-check.mjs` | 휴대폰 시험 빌드가 운영 DB를 가리키면 멈추는지 |
| 화면 흐름 | `scripts/e2e-flow.mjs` | 회원·트레이너 두 사람의 실제 브라우저 흐름(Playwright, 휴대폰 화면 크기) |

시험 계정 닉네임은 `zz검증`으로 시작합니다. 화면 흐름 검증의 캡처는 `test-results/e2e/`에 저장되고 커밋하지 않습니다. 검증 스크립트는 일반 테스트 프레임워크 대신 Node 스크립트의 확인 함수로 짰습니다.

## 브랜치·버전·배포

| 브랜치·태그 | 뜻 |
|---|---|
| `dev` | 테스트 환경에서 작업하는 코드 |
| `main` | 운영에 나간 코드. 운영 배포는 여기서만 합니다 |
| `v1.4.0` 같은 태그 | 그 버전을 운영에 배포한 시점. `npm run deploy`가 붙입니다 |
| `v1.4.0-dev.N` 태그 | dev에서 단계 하나를 끝내 검증을 통과한 시점. `sh scripts/dev-rollback.sh <태그>`로 그 시점의 코드와 로컬 DB 구조로 되돌립니다 |

버전 번호는 운영 배포 기준입니다. `src/lib/releases.ts`의 `APP_VERSION`은 다음 운영 버전이고, dev에서 기능을 여러 번 추가해도 올리지 않습니다.

| 올리는 번호 | 언제 | 앱 안 업데이트 소식 |
|---|---|---|
| N | 앱 구조나 쓰는 방식이 크게 바뀔 때 | 새 항목 |
| M | 새 기능, 눈에 띄는 화면 변경 | 새 항목 |
| L | 기능 추가 없는 버그 수정·문구 | 없음 |

`npm run deploy`는 다음 중 하나라도 걸리면 배포하지 않습니다.

- 지금 브랜치가 `main`이 아님
- 커밋하지 않은 변경이 있음
- 운영 DB에 아직 적용하지 않은 마이그레이션이 있음(조회가 실패해도 중단)
- 버전이 마지막 운영 태그의 바로 다음 번호가 아니거나, 업데이트 소식과 번호가 맞지 않음

배포는 서버 기능(`supabase/functions/*`)과 앱을 같은 커밋으로 올립니다. 서버 기능 배포가 실패하면 앱도 내보내지 않습니다.

```sh
git switch main && git merge dev
npm run db:push      # DB를 바꿨을 때만: 운영 DB에 마이그레이션 적용
npm run deploy       # 운영 배포 + 버전 태그
git switch dev
```

DB를 바꿀 때는 `supabase/migrations/`에 새 파일을 만들고 `npm run db:reset`(로컬 DB를 마이그레이션 전체로 다시 만듦) → `npm run check` → `npm run db:push` 순서로 진행합니다.

## 운영 작업

**PIN 분실** — 트레이너와 운영자는 PIN을 만들어 줄 수 없습니다. 회원이 가입 때 정한 복구 질문에 답하면 본인이 새 PIN을 정합니다. 5번 틀리면 24시간 잠깁니다. 운영자가 직접 PIN을 넣어야 하는 예외 상황에서만 아래 SQL을 씁니다.

```sh
supabase db query --linked "update auth.users set encrypted_password = extensions.crypt('새PIN6자리', extensions.gen_salt('bf')) where id = (select id from public.profiles where lower(nickname) = lower('닉네임'));"
```

**계정 삭제** — 사진은 계정과 함께 지워지지 않으므로 사진 폴더를 먼저 지웁니다. 담당 회원이 남은 트레이너는 지울 수 없습니다.

```sh
supabase storage rm -r "ss:///meal-photos/<회원 id>" --linked --experimental
supabase db query --linked "delete from auth.users where id = '<회원 id>';"
```

**트레이너·운영자 등록 코드 변경** — 새 코드의 SHA-256을 넣습니다. 코드는 대문자로 바꾼 뒤 해시합니다. 운영자 코드는 키 이름만 `admin_code_sha256`로 바꿉니다.

```sh
supabase db query --linked "update public.app_settings set value = encode(extensions.digest(upper('새코드'), 'sha256'), 'hex') where key = 'trainer_code_sha256';"
```

**운영자 화면** — 트레이너 가입 화면의 등록 코드 칸에 운영자 코드를 넣고 가입하면 운영자 계정이 됩니다. 운영자는 익명 의견과 보안 기록(신고·되찾기·잠김·닉네임 변경)을 보며, 식단과 회원 기록은 볼 수 없습니다. 의견 테이블(`app_feedback`)에는 작성자 칸이 없습니다.

**푸시 알림 송신 스위치** — 전체를 멈추거나 시험 계정에만 보낼 수 있습니다. 처음 운영에 켤 때는 `testers`로 두고 실제 휴대폰 두 대에서 받는 것을 확인한 뒤 `all`로 엽니다. 운영 키와 비밀 등록은 `scripts/push-prod-setup.mjs`가 합니다.

```sh
supabase db query --linked "update public.app_settings set value = 'off' where key = 'push_mode';"      # 모두 멈춤
supabase db query --linked "update public.app_settings set value = 'testers' where key = 'push_mode';"  # push_testers(사용자 ID, 쉼표로 구분)만
supabase db query --linked "update public.app_settings set value = 'all' where key = 'push_mode';"      # 모두
```

## 알아 둘 점

- 로그인은 Supabase의 이메일·비밀번호 방식을 그대로 씁니다. 이메일 자리에는 닉네임 해시로 만든 가짜 주소(`…@users.mealnote.local`)가 들어가고 메일은 보내지 않습니다.
- 로그인은 로그아웃 전까지 유지됩니다. 다만 아이폰 사파리는 그 사이트를 7일간 쓰지 않으면 저장소를 지워 로그인이 풀립니다. 홈 화면에 추가한 앱은 따로 계산합니다.
- 목록은 최근 60일과 아직 확인하지 않은 식사를 불러옵니다. 기록 화면에서 더 오래된 날짜를 고르면 그날만 따로 불러옵니다.
- 화면이 열려 있으면 1분마다, 앱으로 돌아올 때마다 새 식사와 댓글을 다시 불러옵니다. 화면 밖에서는 푸시 알림(v1.7)이 새 소식을 알립니다.
- 새 버전은 앱으로 돌아올 때와 켜 둔 동안 30분마다 확인합니다. 입력 중이 아니면 조용히 적용하고, 입력 중이면 '지금 적용' 띠를 띄운 뒤 다음에 돌아올 때 적용합니다(`src/lib/appUpdate.ts`).
- Supabase 무료 프로젝트는 일주일간 요청이 없으면 일시 정지됩니다. 대시보드에서 다시 켭니다.
- `wrangler pages` 명령이 Workers 방식으로 넘어가려 하면 설정 파일을 바꿔 놓습니다. 이 프로젝트는 Pages 방식이라 `npm run deploy`만 씁니다.

## 파일 구성

| 경로 | 내용 |
|---|---|
| `src/App.tsx` | 로그인 여부와 역할(회원·트레이너·운영자)에 따라 화면을 고릅니다 |
| `src/member/`, `src/trainer/`, `src/admin/` | 역할별 화면 |
| `src/components/` | 공용 화면 조각(식사 카드·상세·입력 창, 알림 설정, 업데이트 띠 등) |
| `src/lib/` | 상태 판정(`status.ts`), 서버 호출(`api.ts`), 로그인·PIN·복구, 알림, 새 버전 적용, 인바디 인식, 업데이트 소식(`releases.ts`) |
| `supabase/migrations/` | 테이블·권한 규칙·서버 함수·알림 생성 작업. 파일 이름의 날짜 순서로 적용합니다 |
| `supabase/functions/send-push/` | 웹 푸시를 실제로 보내는 서버 기능 |
| `scripts/` | 검증·배포·되돌리기·알림 준비·휴대폰 시험 스크립트 |
| `public/guides/notifications/` | 알림 설정 안내 그림(실제 기기 캡처가 아닌 설명용 재구성) |
