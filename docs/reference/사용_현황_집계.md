# 사용 현황 집계

README의 그래프는 매일 한국시간 00:20에 전날까지의 기록으로 갱신합니다. GitHub Actions에서 실행하므로 개인 컴퓨터를 켜 둘 필요가 없습니다. 예약 실행은 GitHub 사정에 따라 지연될 수 있습니다.

## 무엇을 세는가

| 지표 | 기준 |
|---|---|
| 가입 회원 | 해당 날짜까지 가입한 회원. 트레이너·관리자·테스트 계정 제외 |
| 활성 회원 | 해당 날짜에 식단을 한 건 이상 작성한 회원. 여러 건을 써도 한 명으로 집계 |
| 식단 기록 | 해당 날짜까지 작성된 식단 기록의 총수. 테스트 계정의 기록 제외 |

모든 날짜는 한국시간으로 계산합니다. 식사한 날짜인 `eaten_on` 대신 앱에 기록을 등록한 시각인 `created_at`을 사용합니다. 어제 먹은 식사를 오늘 등록하면 오늘의 활성 회원과 기록 건수에 포함합니다. 댓글·평가·기존 기록 수정은 새 식단 작성으로 세지 않습니다. 기록이 없는 날의 활성 회원은 0명입니다.

처음에는 현재 DB에 남아 있는 회원과 식단의 생성 시각으로 과거 값을 복원했습니다. 이후에도 같은 기준으로 다시 집계합니다. 계정이나 식단을 삭제하거나 테스트 계정으로 바꾸면 과거 값도 달라질 수 있습니다. 삭제된 기록까지 보존하는 가입·작성 이력 통계는 아닙니다.

집계 JSON에는 전체 기간을 보관하고, 그래프는 최근 90일을 표시합니다. 누적 값은 그래프에 보이는 기간 이전의 가입과 기록도 포함합니다.

## 어떻게 갱신하는가

1. [`daily-usage.yml`](../../.github/workflows/daily-usage.yml)이 예약 시각 또는 수동 실행 요청에 따라 시작합니다.
2. 집계 전용 DB 계정으로 `portfolio_metrics.daily_usage`를 조회합니다. 이 뷰는 날짜·가입 회원 수·활성 회원 수·식단 기록 수만 반환합니다.
3. 날짜 누락, 오늘 날짜 포함, 잘못된 값, 허용하지 않은 필드를 검사합니다.
4. [`update.py`](../../scripts/metrics/update.py)가 [집계 데이터](../data/usage.json), PC·모바일용 그래프, README의 한국어·영어 사용 현황을 갱신합니다.
5. 변경된 파일만 main에 커밋합니다. 집계나 그래프 생성이 실패하면 기존 공개본을 유지합니다.

GitHub의 Actions → **Update daily usage** → **Run workflow**에서 수동으로 다시 실행할 수 있습니다. 같은 데이터로 반복 실행해도 중복 행이나 불필요한 변경을 만들지 않습니다. README 본문은 `usage-metrics`와 `usage-metrics-en` 주석 사이만 자동으로 바꿉니다.

## 연결과 권한

집계 계정은 회원·식단 원본 테이블에 대한 조회·수정 권한 없이 집계 뷰만 읽습니다. 연결 정보는 GitHub Actions의 `METRICS_DATABASE_URL` 비밀값으로 보관하며, 공개 파일과 실행 로그에는 쓰지 않습니다. 앱의 관리자 키나 데이터베이스 소유자 비밀번호를 자동화에 넣지 않습니다.

[`setup.sql`](../../scripts/metrics/setup.sql)은 집계 뷰와 읽기 역할을 구성하는 SQL입니다. 앱 테이블의 데이터와 기존 접근 정책은 바꾸지 않습니다. 역할에 로그인 비밀번호를 부여하고 GitHub 비밀값을 등록하는 일은 운영 환경에서 별도로 수행합니다.

공개되는 것은 일별 집계 숫자입니다. 닉네임, 회원 ID, 사진, 식단 내용은 집계 결과에 포함하지 않습니다.
