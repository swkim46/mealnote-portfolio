# 제가 다니는 센터에 필요한 기능부터 정했습니다

[식단노트](../README.md) / 설계 기록 1

처음 만들 앱은 제가 다니는 PT센터에서 쓸 식단 기록 서비스였습니다. 개인 카카오톡으로 식단 사진을 보내기 부담스러워하는 회원들을 위해 트레이너가 제안했습니다. 저도 그런 회원 중 하나였기에 직접 만들어 보기로 했습니다.

## 식사 기록에서 피드백 확인까지

[첫 기획안](reference/식단관리앱_개발기획안_v1_0.md)은 회원의 기록과 트레이너의 피드백을 한 식사에 묶었습니다. 이후 개발 범위를 바꿔도 이 과정은 유지했습니다.

- **회원이 식사를 남깁니다.** 사진과 함께 먹은 시각·음식·트레이너에게 보낼 메시지를 기록합니다. 나중에 올린 식사도 구분할 수 있게 먹은 시각과 등록 시각을 따로 둡니다.
- **트레이너가 할 일을 확인합니다.** 첫 화면에서 아직 처리하지 않은 식사를 보고, 식사별로 확인·평가·답변합니다.
- **회원이 피드백을 읽습니다.** 답글은 해당 식사에 붙이고, 새 피드백을 표시합니다. 별도 채팅방을 만들지 않아도 어떤 식사에 관한 이야기인지 함께 볼 수 있습니다.

트레이너가 식사를 열어 보기만 했다고 처리를 끝내지는 않습니다. 확인과 피드백을 남기는 동작을 두고, 이후 직접 써 보며 확인만 할 메시지와 답변할 메시지를 나눴습니다. 이 결정은 [트레이너 업무 흐름](02_트레이너_업무_흐름과_처리_규칙.md)에서 자세히 설명합니다.

## 초안의 규모를 실제 사용 대상에 맞췄습니다

첫 기획안은 회원 100명·트레이너 5명 규모의 스토어 앱과 센터 관리자 웹을 외주로 만드는 안이었습니다. 제가 다니는 센터의 트레이너와 회원들이 사용할 앱이고, 개발도 제가 AI 도구를 활용해 진행할 계획이었습니다. 이 조건에 맞게 범위를 다시 잡도록 요구했습니다([변경 기록](../CHANGELOG.md) v1.1).

다음 판에서는 링크로 전달하는 모바일 웹앱(PWA)을 택했습니다. 회원은 링크를 받아 사용하고 휴대폰 홈 화면에도 추가할 수 있습니다. 스토어 배포를 거치지 않아도 되는 방식입니다. 첫 기획안에서는 소규모 검증용 대안이었던 방식을 실제 만들 제품으로 정했습니다.

가입도 닉네임과 숫자 6자리 PIN으로 정했습니다. 이메일·전화번호를 받지 않으면서 메일 발송 서비스와 도메인 구매가 빠졌고, 담당 트레이너는 회원이 가입할 때 고르게 했습니다. 연락처를 받지 않는 가입은 이후 계정 복구 방식에도 영향을 줬습니다([가입과 계정 보안](03_가입과_계정_보안.md)).

## 기획안 세 판에서 달라진 선택

기획안을 세 차례 다듬으며 서비스 규모와 개발 방식을 정했습니다. 각 기획안에서 제안한 내용은 다음과 같습니다.

| 항목 | v1.0 | v1.1 | v1.2(첫 구현의 기준) |
|---|---|---|---|
| 대상 | 회원 100명, 트레이너 5명, 센터 1곳 | 트레이너 5명 이하, 소수 회원 | v1.1과 같음 |
| 개발 | 외주 개발을 전제로 인력·기간·예산 산정 | Codex·Claude Code로 직접 개발 | v1.1과 같음 |
| 형태 | 스토어 앱과 센터 관리자 웹 | 스토어 앱 | 링크로 전달하는 모바일 웹앱(PWA) |
| 가입 | 이메일 가입 | 이메일 로그인 | 닉네임과 6자리 PIN |
| 담당 연결 | 관리자가 배정 | 운영자가 관리 화면에서 배정 | 트레이너가 먼저 가입하고 회원이 선택 |
| 알림 | 앱 푸시 | 앱 푸시 | 앱 안 표시부터, 웹 푸시는 후속 |
| 비용 가정 | 외주 개발 예산 추정 | 무료 서비스 요금부터, 스토어 계정비 별도 | Supabase·Cloudflare Pages 무료 플랜 |

원문: [v1.0](reference/식단관리앱_개발기획안_v1_0.md) · [v1.1](reference/식단관리앱_개발기획안_v1_1.md) · [v1.2](reference/식단관리앱_개발기획안_v1_2.md)

칼로리 자동 분석·결제·별도 채팅방·센터 관리자 웹은 범위에서 제외했습니다. 첫 버전은 기록과 피드백에 집중했습니다. 이후 v1.4에서 인바디 기록을, v1.7에서 휴대폰 알림을 추가했습니다. 트레이너의 PIN 재설정은 v1.2에 넣었다가 계정 권한 문제로 v1.3에서 없앴습니다.

## 실제 사용으로 이어진 범위

기획안 v1.2를 기준으로 화면 시안을 만들고 앱 v1.0을 배포했습니다. 시안은 [단일 HTML 파일](reference/식단관리앱_와이어프레임_v1_0.html)로 남아 있습니다. 앱의 처리 규칙도 이 시안에서 출발했습니다([`status.ts`](../src/lib/status.ts#L1-L3)).

담당 트레이너와 제가 먼저 써 본 뒤, 센터의 다른 회원들도 사용하기 시작했습니다. 가입과 사용 현황은 [README](../README.md#실제-사용-현황)에 정리했습니다.

현재는 식단에서 출발해 운동 루틴과 인바디 변화까지 함께 보는 방향을 구상하고 있습니다. 후속 기능은 [앞으로의 계획](07_앞으로의_계획.md)에 현재 기능과 나눠 적었습니다.
