# 식단노트 — PT샵 트레이너와 회원이 함께 쓰는 식단 기록·피드백 웹앱

> **Summary (English)**
> Mealnote is a mobile web app (PWA) used at one personal-training studio. Members log each meal with a photo, and their trainer reviews, rates and replies to it in one queue. My trainer suggested the idea because many members felt uncomfortable sending meal photos through the trainer's personal messenger.
> I defined the scope, the product rules (for example, separating "needs review" from "needs a reply", and letting trainers acknowledge a message without replying), the notification policy and the release process. Claude Code implemented the code, and Codex reviewed plans and code; I decided which review findings to apply and when to release.
> The first version went live on 2026-10-20. By 2026-10-28 it had 2 trainers and 26 members, including me.
> Stack: React, Vite, Supabase (Postgres row-level security, Edge Function, pg_cron), Cloudflare Pages, Web Push.
> This repository is a sanitized copy of the private production repository. The production URL, project identifiers and real user data are removed.

회원이 끼니마다 사진과 함께 식사를 기록하면, 담당 트레이너가 한 목록에서 확인하고 평가와 답글을 남깁니다. 회원이 그 피드백을 읽었는지, 트레이너가 답해야 할 말이 남았는지도 앱이 함께 셉니다. PT샵 한 곳의 트레이너와 회원이 실제로 쓰고 있습니다.

## 1. 왜 만들었나

회원들은 식단 사진을 트레이너의 개인 카카오톡으로 보냈습니다. 트레이너는 개인 메신저로 사진을 보내는 것을 부담스러워하는 회원이 많아 식단 관리가 잘 이어지지 않는다고 했고, 저도 그래서 사진을 보내지 않던 회원이었습니다. 트레이너의 아이디어를 받아, 회원은 식사만 남기고 트레이너는 담당 회원의 기록을 한곳에서 확인하는 서비스를 만들었습니다.

첫 기획안에서 정한 방향은 두 가지입니다. 트레이너에게는 사진만이 아니라 식사 시각·음식·남긴 말·답변 대기 여부를 함께 보여 주고, 피드백은 범용 메신저가 아니라 식사 기록에 붙은 대화로 주고받습니다([기획안 v1.0](docs/reference/식단관리앱_개발기획안_v1_0.md)).

## 2. 제품 규칙과 결정

### 2.1 외주 앱 기획에서 직접 만드는 웹앱으로 범위 축소

첫 기획안(10월 20일)은 회원 100명·트레이너 5명 규모의 스토어 앱과 관리자 웹을 외주로 만드는 안이었습니다. 저는 같은 날 범위를 직접 개발·트레이너 5명 이하·소수 회원으로 줄이도록 고쳤고, 다음 판에서 스토어 앱 대신 링크로 전달하는 모바일 웹앱(PWA)을 택했습니다. 인프라는 Supabase와 Cloudflare Pages의 무료 플랜으로 월 0원입니다. 칼로리 자동 분석·결제·별도 채팅방·관리자 웹은 범위에서 뺐습니다. 세 판의 비교는 [문제와 범위 결정](docs/01_문제와_범위_결정.md)에 있습니다.

### 2.2 트레이너의 할 일을 '확인'과 '답변'으로 나눈 규칙

10월 21일 회원·트레이너 화면을 직접 써 보며 두 가지를 발견했습니다. 회원이 식사를 등록할 때 남긴 말은 사진 아래 작은 회색 글씨라 트레이너가 놓치기 쉬웠습니다. 또 회원의 말이 마지막으로 남아 있으면 트레이너가 답글을 써야만 답변 대기에서 빠져서, '감사합니다' 같은 말에도 답을 달아야 했습니다.

그래서 트레이너가 처리할 일을 확인할 식사와 답할 말로 나눠 셉니다. 등록 때 남긴 말은 대화의 첫 메시지로 바꿔 답변 대기로 잡고, 답할 말이 있는 식사를 목록 맨 위에 올립니다. 답이 필요 없는 말은 '답변 없이 확인'으로 정리하고, 확인한 뒤 회원이 새로 말을 남기면 다시 답변 대기로 올라옵니다([`status.ts`](src/lib/status.ts#L26-L38), [확인 목록 정렬](src/trainer/TrainerApp.tsx#L121-L124)). 푸시 알림을 붙일 때는 서버의 알림 판정도 같은 규칙으로 옮겼습니다([SQL 판정](supabase/migrations/20261026000002_push.sql#L21-L28)). 자세한 내용은 [트레이너 업무 흐름과 처리 규칙](docs/02_트레이너_업무_흐름과_처리_규칙.md)에 있습니다.

### 2.3 연락처 없이 닉네임과 PIN으로 가입, 계정 복구는 본인만

가입에는 이메일·전화번호를 받지 않고 닉네임과 숫자 6자리 PIN만 씁니다. 트레이너는 운영자가 나눠 준 등록 코드로 먼저 가입하고, 회원은 가입할 때 담당 트레이너를 고릅니다. PIN 분실은 v1.2에서 담당 트레이너가 새 PIN을 만들어 주는 방식이었는데, Codex 리뷰가 트레이너가 회원 몰래 계정을 가져갈 수 있다고 지적했습니다. v1.3에서 트레이너 재설정을 없애고, 가입 때 정한 복구 질문에 본인이 답해 새 PIN을 정하도록 바꿨습니다. 5번 틀리면 24시간 잠기고, PIN이 바뀌면 로그인해 둔 다른 기기에서 계정을 되찾을 수 있습니다. 경위는 [가입과 계정 보안](docs/03_가입과_계정_보안.md)에 있습니다.

### 2.4 알림: 트레이너에게는 모아서, 회원에게는 바로

트레이너에게는 회원마다 알림을 보내지 않고, 확인할 기록과 답할 질문의 건수를 하루 3회(선택하면 5회) 모아서 보내도록 정했습니다. 회원에게는 트레이너가 피드백을 남기면 바로 보냅니다. 처음 계획은 3분 기다려 묶어 보내는 것이었는데, 구현 중에 바로 보내도록 바꿨습니다(10월 27일). 낮 1시와 저녁 8시에는 그 끼니 기록이 없을 때만 기록 알림을 보냅니다. 잠금 화면에는 이름과 식단 내용 없이 건수와 종류만 씁니다. 운영에 처음 켤 때는 송신 스위치를 시험 계정에만 열어 두 휴대폰에서 받는 것을 확인한 뒤 전체로 열었습니다. 결정 목록과 리뷰 반영은 [알림 설계](docs/04_알림_설계.md)에 있습니다.

### 2.5 출시 뒤에도 실제 사용자를 지키는 운영 방식

버전 번호는 운영 배포를 기준으로 N.M.L로 매기도록 정했습니다(10월 21·23일). 배포 명령은 `main`이 아니거나, 커밋하지 않은 변경이 있거나, 운영 DB에 적용하지 않은 마이그레이션이 있으면 멈춥니다([`deploy.sh`](scripts/deploy.sh#L6-L43)). 개발은 맥 안의 로컬 DB에서 하고 운영 DB와 나눴습니다. 새 버전은 자동으로 적용하되, 입력 중인 글이 있으면 적용을 미룹니다([`appUpdate.ts`](src/lib/appUpdate.ts#L39-L74)). 이 동작은 Codex 리뷰가 초안이 지워지는 경로를 찾을 때마다 보강했습니다. 자세한 내용은 [출시 후 운영](docs/05_출시_후_운영.md)에 있습니다.

## 6. 공개 범위

- 이 저장소는 비공개 운영 저장소의 `main`(v1.7.2, 운영 커밋 `877632d`)을 공개용으로 정리한 사본입니다. 그래서 이 저장소의 커밋 이력은 공개본을 만든 시점부터 시작하고, 변경 기록 속 커밋 번호와 태그는 운영 저장소의 것입니다.
- 운영 주소와 운영 프로젝트 식별자는 지웠습니다. 문서와 코드의 `https://mealnote.example`은 자리표시자입니다.
- 마이그레이션의 트레이너·운영자 등록 코드 해시는 예시 코드의 해시로 바꿨습니다.
- 실명 닉네임은 일반 이름으로 바꿨고, 실제 사용자의 기록·사진은 싣지 않았습니다. 사용 수치는 운영 DB에서 집계한 숫자만 적었습니다.
- 기획·리뷰 문서는 [`docs/reference/`](docs/reference/)에 원문 그대로 두고 경로·실명·운영 주소만 바꿨습니다. Codex가 리뷰에 쓴 재현 스크립트는 포함하지 않았습니다.
- [변경 기록](CHANGELOG.md)의 '사용자'는 개발을 지시하고 결정한 저를 가리킵니다.
- 라이선스를 두지 않았습니다. 열람은 자유롭지만 코드의 재사용 권한은 주지 않습니다.
